# GIF Creator 视觉词汇与动作语法 v1

状态：用户要求的统一视觉规范；由 Lead 编写。规范已定义，不代表组件全部实现。核心目标为技术博客／科普 GIF，固定符号让不同主题保持一致。不得把下面文字规范当成已经可调用的通用渲染API。

## 1. 语义先于外形

数据、容器、运算、路径、边界、观察点是不同角色，不能统一成圆角文字框。符号相同表示角色相同，不表示每个领域细节相同；标签和单位保留精确含义。颜色辅助身份，形状／文字辅助辨识。每幕5–10秒单知识切片，末尾1–2秒静止；一个焦点可含联动对象组。

## 2. 元素目录

| 角色 / component id | 固定外形 | 具体视觉描述 | 允许动作 | 禁用／误用 |
|---|---|---|---|---|
| 数据记录 / record | 小实心圆角矩形，带短key标签和数值角标 | 白／浅色填充，key色细边，左侧身份色带；count作为明确数字不靠面积表示；默认1280画布宽100–160高40–56 | 移动、标签翻换、复制、合并；焦点边框变亮 | 不以裸文字飞行替代块；不随意改key颜色；移动后源不残留除非复制 |
| 批次／集合 / batch | 2–3层轻微错位的数据块 | 前层实际内容，后层表示集合，不虚构数量；注明n条 | 堆叠、展开成记录、合拢；集合边界稳定 | 层数不冒充记录精确数量 |
| 张量／矩阵 / tensor | 有行列的网格片／轻量叠片 | 维度标注如[N,D]，抽样格标示省略；数值可见或明确示意 | 切片、选区、转置、沿明确轴拼接 | 不靠立方体装饰表达未经定义维度；不能捏造shape |
| 分区／缓冲区 / container | 开口托盘／区域框，有固定标题条 | 淡灰底、灰细边，数据块位于内部，留明显投入口与内容区；角色标签partition/cache/buffer | 容器静止；内容进入／离开／更换；占用变化 | 不让整个容器沿数据路径移动；分区不默认等于机器 |
| 队列 / queue | 带多个明确槽位的横向或纵向通道 | 标head/tail，箭头规定顺序，排队块保持间距 | 入队、出队、前移 | 不把栈或随机访问画成FIFO；空槽非真实数据 |
| 栈 / stack | 单开口竖槽，标top | 新块从顶部进出 | push/pop | 不从底部弹出暗示FIFO |
| 运算／转换 / operator | 小加工门／函数胶囊，输入输出口明确 | 窄竖框配map/filter/+标签；与容器外形区分，不承载长段文字 | 块穿过后标签／值变化，门轻微聚光 | 不用无解释闪光代替转换；无输入输出变化不称运算 |
| 聚合／汇合 / merge | 两个以上输入口汇入一个输出口，配+或明确运算名 | 同key块靠拢，数值相加后生成单块；显示1+1→2的短桥接注释 | 靠拢、折叠成输出块；旧块撤出 | 不只是淡出输入淡入结果；不同key不能合并；保留总量 |
| 路径／通道 / route | 背景细线或低饱和虚线，端点箭头 | 明确从对象边界到对象边界，绕开标签；默认1–2px，低强调；当前段可亮起 | 数据块沿路径行进；路径静止 | 线条不是数据；不让满图粗彩线抢焦点；不穿过第三对象 |
| 网络传输 / transfer | 数据块跨越一条带network标签的边界 | 跨界是含义，不靠随意长距离或弹跳暗示时延；不默认每路径远程 | 块跨界、队列等待（仅来源支持） | 不凭动画速度宣称性能；不把本地移动都标网络 |
| 执行／阶段边界 / boundary | 稳定竖向虚线／区域分割，短标题 | 如shuffle boundary/stage；输入侧输出侧清楚 | 边界静止，数据跨越 | 不等同实际机架／物理机器；执行语义需来源支持 |
| 时间轴／游标 / timeline,cursor | 等距刻度轨道＋细竖线和小三角 | t_k/单位明确；各模态用同一游标，采样间隔非均匀时必须体现 | 游标平滑移动／逐tick，背景不动 | 无来源不得画30FPS为实际配置；不让全部轨道一起滑动 |
| 滑动窗口 / window | 半透明矩形括号跨连续范围 | 覆盖实体而不隐藏内容，注明长度／符号；多模态各自长度独立 | 框移动、截取副本、末尾停留 | 不跨episode；不暗示Nv=Na或范围相同 |
| 摄像头／视觉观测 / camera | 简洁相机轮廓＋独立视野小面板 | 多路相机固定位置与名称，示意画面标合成；相机和帧不同符号 | 面板帧变化，曝光焦点短亮 | 不能把一张示意图当真实机器人视频 |
| 状态向量 / state | q1/q2/q3短条或小数列，包在state框内 | 同一尺度、单位明确；数值变化非纯装饰 | 数值／条长同步游标变化 | 条长不同量纲不可比较；不能捏造关节含义 |
| 动作命令 / action | 带Δ/向量标签的短方向箭头，置于动作块内 | 与路径箭头区分：方向箭头描述命令，不是传输路线 | 向量变化／发送命令块 | action不自动等于执行后真实轨迹 |
| 指针／引用 / pointer | 小三角／细指示线，附明确变量标签 | 端点指向固定槽位／对象 | 指针移动／目标高亮 | 不是数据搬移；避免复制含义 |
| 错误／阻断 / error | 小八边形／断口，文字说明原因 | 红只表示异常，正常key不占红；不只依赖颜色 | 通道暂停、错误对象突出 | 不用大红闪烁或无原因叉号 |
| 注释 / annotation | 短句＋可选轻引线，无大卡片 | 固定保留空白带，14字左右为目标非强行删术语；主标题／单位／来源持续可见 | 阶段出现，淡出后换下一句 | 不跟每个数据块一起漂移；不覆盖对象或一轮堆满 |

## 3. 色彩与排版tokens（1280×720基准）

- 画布浅暖白#F5F3EE；主文字深蓝灰#182B36；静态容器白／淡灰；背景边线#C5CFD2。
- 通用角色：数据／vision蓝#3778BF，state青#168C83，action橙#C8792A；错误独占红。Spark例key身份固定spark蓝、data青、ai橙，不将key颜色称模态色。一个图内只选一种编码语义，不混用。
- 当前对象实色边框+明确标签；非焦点降低边框强调，不降低关键文字到不可读。颜色对比需实际画面检验，不宣称仅靠hex已达WCAG。
- 标题36–44px，说明22–26px，数据块标签22–26px，辅注18–20px；数字等宽字体如系统可读支持。中文不靠缩字塞入；内容过长要求拆分／明确溢出。
- 基础间距8px，块间12–20px，容器内边距20–28px，固定标题/注释/主体/来源四个区，绝不重叠。
- 轻微手绘可选：线条一次性确定性偏移≤1.5px，帧间几何不抖动；数据位置、坐标轴、文字不扭曲。不可把sketch参数只存不执行而宣称支持。

## 4. 动作词汇（优先组合复用）

move=原对象离开原位到目标（非copy）；copy=原对象保持且出现可追踪副本；transform=位置稳定时形态／内容变化；merge=相同组对象靠拢再变单一输出（守恒、规则明确）；split=来源对象拆为多个可解释部分；select=只改变焦点，不搬移；scan=游标／窗口沿固定参照推进；enqueue/dequeue=沿明确队列规则；hold=最后完整状态静止；reset=结束直接回起点，不追加眩晕式倒放。

运动节奏：起步／停止柔和，但不夸张弹跳。同阶段最好一个主体或一个有共同含义的组。聚合故事先建立输入→显现关键变化→结果揭示，不把整图同时FadeIn当叙事。数据块需要清楚轮廓和标签，曲线为辅助，主体数量／尺寸以可追踪为准；并行操作分组渐次发生，避免路径乱线。

## 5. 创作输入和质量门（待按次序实现）

每个模板声明：question（读者的问题）、visualRoles（符号角色）、anchors（保持静止的对象）、focus（当前主体）、beats（输入／关键变化／结果）、invariants（key、数量、单位、范围守恒）、finalHold。模板不允许自由code/eval。

自动检查：布局／文字边界；5–10秒／末停1–2秒解码；实体不穿第三对象；move结束源撤出copy则保留；语义守恒；固定锚点稳定；来源与合成标识。视觉人工检查：能否追踪数据、是否一眼找到焦点、动作是否解释机制、是否退化成满屏线条／长文字卡片。自动分数不证明故事好懂，不伪造人工reviewapproval。

Spark首验：record块→map标签→同key本地靠拢合并→穿shuffle边界→目标托盘同key汇合→最终数值。线条低饱和辅助；8秒末停2秒。VLA后续采用同一record/container/timeline/window/action/state词汇，不另起随机风格。

## 6. 跨领域适配：统一语法、保留专业差异

核心场景：学术论文／计算机／AI／软件工程／系统设计，优先深度学习、统计学习、分布式系统。统一的是符号角色与动作含义，不是把每领域都画成流水线。

| 场景 | 主体符号与动作 | 固定参照 | 必须保留的科学边界 |
|---|---|---|---|
| 深度学习：前向／反向 | 张量网格穿过operator；前向激活与反向梯度用方向＋标签区分；参数块更新 | 网络模块／维度标签固定 | 梯度非真实数据流／反向不等于倒放；更新来自明确梯度规则 |
| 深度学习：attention | token块、Q/K/V矩阵、打分热图、加权汇合 | token顺序／mask／轴固定 | 区分logits与softmax权重；行归一化、mask、维度明确；热图非装饰 |
| 深度学习：MoE | token块进入router再分组到expert托盘，输出按原token位置归并 | experts／token槽位固定 | top-k、权重、容量／丢弃仅来源支持；不暗示所有expert串行 |
| 深度学习：优化 | 参数点沿损失等高线移动，梯度箭头／更新向量分别标记 | 同一损失坐标／尺度固定 | 合成二维示意不等于真实高维轨迹；LR／动量数值不伪造 |
| 统计学习：抽样 | 样本点从总体示意区抽取，样本统计量进入估计分布 | 总体尺度、样本槽／坐标固定 | 抽样机制／样本量明确；不能用分布动画暗示因果 |
| 统计学习：估计与不确定性 | 数据点、拟合线、误差条／区间带；重复样本显示估计变化 | 同一轴／目标量固定 | 置信区间与预测区间不同；贝叶斯可信区间不可混称；不编概率解释 |
| 统计学习：偏差方差 | 同数据／同轴下模型曲线与重复估计分组显示 | train/test标识／参照函数固定 | 误差分解条件、合成真值明确；不要靠曲线抖动冒充量化方差 |
| 分布式：通信／shuffle | record／message块跨节点／分区边界，排队、路由、聚合 | node／partition托盘稳定 | 分区≠机器；传输≠全内存复制；map-side combine／shuffle语义准确 |
| 分布式：复制／一致性 | 带版本号日志条目复制到replica槽，ack消息返回，commit位置推进 | leader/follower角色／term／日志索引固定 | append/ack/commit/apply区分；不把多数确认画成全副本同步 |
| 分布式：故障／重试 | 断口阻断消息、计时器／重试块、去重键突出 | 时序／请求身份固定 | at-least-once不等于exactly-once；重复／幂等／超时边界明确 |
| 系统设计：缓存／队列 | 请求块进入缓存或DB容器；命中返回，未命中沿旁路；队列head推进 | 缓存／DB／worker固定 | TTL／击穿／穿透不同；无依据不展示latency或吞吐数值 |

提供两个表现预设（待实现，不声称现有可选）：论文图式用准确几何、符号、公式与克制强调；技术博客用具象小插画与运动实体。两者共享组件身份、数据坐标、标签和动作规则。手绘仅可选，不扭曲数学／统计尺度。不可照搬特定创作者独有画风或伪称其授权。

## 7. 多视图组合规则

一个GIF可以组合系统结构、数据流、数学解释和统计视图，但共享字体、配色、实体身份与事件时钟。先用时间、空间、归属、依赖、数量、状态、反馈多维关系建模，再选择对齐轨道、矩阵对应、嵌套区域、聚合中心、反馈环或结构／数量联动等布局；不以一个DSL或线性流程替代完整关系模型。焦点是一个关系组，不是最多两个轨道的硬限制。多空间位移、形状转换、有来源的尺寸编码、协同运动与协同数值更新分别声明含义；无来源不把大小／速度当定量结论。上述是设计技巧，通用renderer尚未实现这些布局。结构／坐标固定；每个阶段一个主焦点组；系统节点的活跃态必须与数据块位置或明确计算事件同步。公式和曲线只能表达有依据的规则／数据，不为了视觉丰富捏造数值。

DSL分工可参考D2的分组布局、Mermaid／PlantUML的关系和时序、Vega的数据编码。当前DSL导入仅支持明确安全子集，转换为既有graph/chart分镜；通用多视图联动尚未实现。不能把完整静态DSL图片拼贴后淡入淡出称为机制动画。

## 8. 交付边界

此文档是统一词汇规范。当前renderer尚非全组件通用引擎；Spark模板已实现带身份色带的实体数据块与Shuffle动画；其他模板仍需逐项实现和验证。只有已实际实现/渲染/测验的组件才能在工具描述中标为可用。新模板需引用此规范，避免重复定义身份颜色/容器形状/动作语义。
